# Шпаргалка для техподдержки

[English](SUPPORT.md) | [Русский](SUPPORT.ru.md)

Знать Vault, Kubernetes и GitLab не нужно. Ваша задача: превратить заявку в небольшую правку одного YAML-файла, открыть merge request и прочитать, что скажет автоматическая проверка.

## Порядок действий (5 минут)

1. Найдите в заявке **команду** ресурса и откройте файл её направления (`access/web.yml`, `access/infr.yml`, ...). Найдите имя команды поиском.
2. Сделайте **одну** из правок ниже. Номер заявки пишите в `ticket:`.
3. По возможности проверьте локально: `access-as-code lint access` (ничего не установлено? пропустите, CI проверит сам).
4. Откройте merge request с номером заявки в заголовке. CI проверит его, владельцы файла отревьюят. После слияния автоматизация применит изменения.

Полезные вопросы до правки: `access-as-code who access alice` («что сейчас у Alice?») и `access-as-code matrix access` (обзор по командам).

## Рецепты

Отступы - пробелы, не табы. Имена строчными (`alice`, `sys-adm`). Дата - `YYYY-MM-DD`.

### 1. Новый сотрудник пришёл в команду
Добавьте `логин: корпоративная почта` в `members`. Логин должен совпадать с логином в Kubernetes/Vault/GitLab; на почту придут данные его учётной записи, поэтому это должен быть его собственный корпоративный адрес (не личный). Стандартный доступ команды появится автоматически.
```yaml
    members:
      alice: alice@corp.example
      newbie: newbie@corp.example      # <- добавили строку
```

### 2. Сотрудник уволился
Перенесите имя из `members` (строку `логин: почта` удалите целиком) в `left` и удалите все строки с ним в `extra` (во **всех** файлах: `grep -rn имя access/`).
```yaml
    members: [alice, bob]
    left: [newbie]
```
Если строку забыли, CI упадёт с `AAC005 ... 'newbie' is offboarded`. Слить нельзя, пока не исправите.

### 3. Временный доступ в production (релиз, расследование)
Добавьте строку в `extra`. Для production нужны `ticket` и `expires` (не дальше 90 дней).
```yaml
    extra:
      - { who: alice, role: deployer, env: prod, ticket: SEC-210, expires: 2026-11-30 }
```
Несколько человек с одинаковым доступом: `who: [alice, bob]`.

### 4. Аварийный доступ («break glass»)
Только с заявкой на инцидент, не более 7 дней, с указанием причины:
```yaml
      - { who: erin, role: break-glass, env: prod, ticket: SEC-220, expires: 2026-10-12, reason: "incident INC-77" }
```

### 5. Человеку из другой команды нужен доступ
Запись пишется в файле/команде, **которой принадлежит ресурс** (не команде человека). Нужен тикет, иначе CI предупредит `AAC008`.
```yaml
  devops:
    extra:
      - { who: alice, role: viewer, env: stage, ticket: SEC-230 }
```

### 6. Продлить или убрать доступ
Продлить: измените `expires` (и тикет, если это новая заявка). Убрать: удалите строку. Просроченные строки нужно удалять, иначе CI падает с `AAC006`; за 14 дней до даты появляется предупреждение `AAC011`.

### 7. Изменить, что получает вся команда
Правьте блок `access:` команды. Это затрагивает всех, поэтому ревьюеры посмотрят внимательно.
```yaml
    access:
      dev: developer
      stage: developer
      prod: { role: viewer, ticket: SEC-101 }
```

### 8. Новая команда
Скопируйте блок команды в `teams:` файла её направления и переименуйте. Сначала попросите платформенную команду создать mount Vault `kv-<team>` и namespace'ы Kubernetes `<team>-dev|stage|prod`.

## Роли простыми словами

| Роль | Может |
|---|---|
| `viewer` | только читать |
| `developer` | работать в окружении: читать секреты, менять нагрузки, пушить код |
| `deployer` | всё, что `developer`, плюс писать секреты и выпускать релиз |
| `approver` | согласует релизы в production (не может быть тем же человеком, что `deployer`, AAC007) |
| `break-glass` | авария, может удалять; максимум 7 дней |

Не знаете, какую роль? Спросите автора заявки, что нужно *делать*, и выберите наименьшую роль. Полный список - в `access/common.yml`.

## Как читать ошибки CI

`access-as-code explain AAC003` покажет полное объяснение любого кода. Частые:

| Сообщение | Что делать |
|---|---|
| `AAC003 ... production grant without a ticket` | добавить `ticket: SEC-123` |
| `AAC003 ... direct production grant without an expiry` / `more than 90 days away` | добавить или сократить `expires:` |
| `AAC004 ... elevated role ... needs a ticket and an expiry within 7 days` | сократить `expires:` у `break-glass` |
| `AAC005 ... is offboarded` | рецепт 2: удалить оставшиеся строки |
| `AAC006 ... expired on ...` | удалить строку |
| `AAC007 ... both deployer and approver` | отдать две роли разным людям |
| `AAC012 ... has no email` | добавить `логин: name@corp.example` в `members` |
| `AAC013 ... share one email address` | у каждого человека свой ящик: исправьте опечатку |
| `AAC014 ... email domain ... is not allowed` | укажите корпоративный адрес, не личный |
| `AAC002 ... unknown ...` | опечатка в имени, либо человек/команда не объявлены |
| `web.yml: teams.sites.extra[1]: 'env' is a required property` | в 2-й строке `extra` команды `sites` файла `web.yml` не хватает поля |
| `person 'x' is defined in web.yml and again in infr.yml` | один логин в двух командах; оставьте одну |

Непонятно - не гадайте, спросите в merge request. Ничто из того, что вы отправите, не меняет реальные доступы, пока не отревьюено и не слито.
